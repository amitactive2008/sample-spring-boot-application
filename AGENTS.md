# AI contributor guide

This file is the source of truth for AI coding agents working in this repository.

## Repository map

- `api-gateway/`: reactive Spring Cloud Gateway; validates JWTs and routes requests.
- `auth-service/`: Spring MVC/JPA service for authentication and user administration.
- `issue-service/`: Spring MVC/JPA service for issue workflows and history.
- `frontend-service/`: React single-page application.
- `docs/`: architecture and local development documentation.
- `security-pipeline.sh`: optional security and quality pipeline.

## Working rules

1. Read `README.md`, `docs/ARCHITECTURE.md`, and the affected module before editing.
2. Keep changes inside the owning service. Do not couple backend services through shared source code.
3. Preserve the public routes: `/auth/**` belongs to auth-service and `/issues/**` belongs to issue-service.
4. Treat DTOs as the API boundary. Do not return JPA entities from controllers.
5. Never commit credentials, tokens, local `.env` files, generated builds, Maven `target/`, or `node_modules/`.
6. Use environment placeholders for deployment configuration. Keep the JWT signing secret identical across all backend services at runtime.
7. Add or update tests with behavior changes. Prefer the smallest relevant test before the full verification suite.
8. Do not edit `frontend-service/build/`; it is generated by `npm run build`.

## Verification

Run the checks appropriate to the files changed:

```bash
./scripts/verify.sh backend
./scripts/verify.sh frontend
./scripts/verify.sh all
```

Backend tests use isolated H2 databases and a test-only signing key. When another check cannot run because a local dependency is absent, report the exact command and failure. Do not silently skip verification.

## Style

- Java: Java conventions, four-space indentation, constructor injection, focused classes.
- React: functional components, two-space indentation, API calls through `src/api/`.
- Documentation: update commands, variables, routes, or architecture in the same change that alters them.
- Git: keep commits focused and use imperative subjects such as `Add issue status validation`.
