# AI contributor guide

This file is the source of truth for AI coding agents working in this repository.

## Read first

Before editing, read `README.md`, `docs/ARCHITECTURE.md`, the owning service, and
the relevant Helm template or values file. Use `rg` and `rg --files` to navigate.

## Repository map

- `api-gateway/`: reactive Spring Cloud Gateway; validates JWTs and routes requests.
- `auth-service/`: Spring MVC/JPA authentication and user administration service.
- `issue-service/`: Spring MVC/JPA issue workflow and history service.
- `frontend-service/`: React single-page application; API clients live in `src/api/`.
- `helm/issue-tracker/`: application, MySQL, Gateway API, and TLS resources.
- `kind/`: local Kind cluster configuration and host-port mappings.
- `scripts/`: repeatable verification and Podman/Kind deployment helpers.
- `docs/`: architecture and contributor-facing technical documentation.

## Working rules

1. Keep changes inside the service that owns the behavior. Do not couple backend
   services through shared Java source or repositories.
2. Preserve public routes: `/auth/**` belongs to auth-service and `/issues/**`
   belongs to issue-service. External cluster traffic enters through `/api/**`.
3. Treat DTOs as API boundaries. Controllers must not return JPA entities.
4. Keep local defaults in `values.yaml` and production overrides in
   `values-prod.yaml`. Never put real credentials in either file.
5. Never commit tokens, local `.env` files, kubeconfigs, image archives, scanner
   workspaces, reports, Maven `target/`, `node_modules/`, or React `build/`.
6. Keep the JWT signing secret identical across all backend services at runtime.
7. Do not edit `frontend-service/build/`; it is generated by `npm run build`.
8. Update documentation with changes to commands, variables, routes, ports, or
   deployment relationships.
9. Add or update tests with behavior changes. Run the smallest relevant check first.
10. Preserve rootless Podman and Kind compatibility.

## Verification

Run checks appropriate to the files changed:

```bash
./scripts/verify.sh backend
./scripts/verify.sh frontend
./scripts/verify.sh helm
./scripts/verify.sh shell
./scripts/verify.sh all
```

If a required local dependency is unavailable, report the exact command and
failure. Do not silently skip verification.

## Style

- Java: four-space indentation, constructor injection, and focused classes.
- React: functional components, two-space indentation, and API calls through `src/api/`.
- Helm: keep environment differences in values files and quote string values.
- Shell: use `set -euo pipefail`, quote variables, and prefer non-interactive commands.
- Git: focused commits with imperative subjects, such as `Validate Helm deployment`.
