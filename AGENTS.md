# AI contributor guide

This file is the source of truth for AI coding agents working in the v2 branch.

## Read first

Before editing, read `README.md`, `docs/ARCHITECTURE.md`, `docker-compose.yml`, and the
affected module. Use `rg` or `rg --files` to navigate the repository.

## Repository map

- `api-gateway/`: reactive Spring Cloud Gateway; validates JWTs and owns public routing.
- `auth-service/`: Spring MVC/JPA authentication and user administration service.
- `issue-service/`: Spring MVC/JPA issue workflow and history service.
- `frontend-service/`: React single-page application; HTTP clients live under `src/api/`.
- `docs/`: architecture and focused operational documentation.
- `scripts/`: repeatable local verification helpers.
- `docker-compose.yml`: v2 container topology and local runtime configuration.
- `security-pipeline.sh`: optional extended security and container-quality pipeline.

## Working rules

1. Keep changes inside the service that owns the behavior. Do not couple backend services
   through shared Java source or direct database access.
2. Preserve the public routes: `/auth/**` belongs to auth-service and `/issues/**` belongs
   to issue-service. External requests enter through api-gateway.
3. Treat DTOs as API boundaries. Controllers must not return JPA entities.
4. Keep secrets out of source control. Use `.env.example` for names and safe examples;
   keep `.env`, tokens, keys, and real credentials local.
5. The same `JWT_SECRET` must be supplied to all backend containers at runtime.
6. Do not edit `frontend-service/build/`; it is generated by `npm run build` and ignored.
7. Do not commit Maven `target/`, `node_modules/`, reports, local caches, or container data.
8. Update documentation in the same change when commands, routes, environment variables,
   profiles, ports, or container relationships change.
9. Add or update tests with behavior changes. Prefer the smallest relevant test first.
10. Preserve rootless Podman compatibility and non-root application containers.

## Verification

Run the checks appropriate to the files changed:

```bash
./scripts/verify.sh backend
./scripts/verify.sh frontend
./scripts/verify.sh containers
./scripts/verify.sh all
```

`all` runs backend and frontend checks. Container validation is separate because it
requires `podman-compose`. If a required local dependency is unavailable, report the
exact command and error; do not silently skip it.

For changes to security tooling, also run:

```bash
bash -n security-pipeline.sh
```

## Style

- Java: four-space indentation, constructor injection, focused classes, Java conventions.
- React: functional components, two-space indentation, API calls through `src/api/`.
- Shell: `set -euo pipefail`, quoted variables, deterministic non-interactive commands.
- Documentation: concise commands that can be copied directly, with destructive steps
  labeled explicitly.
- Git: focused commits with imperative subjects such as `Add container health validation`.
